# 联机游戏厅 🎲

一个可以在浏览器里和同学开房间一起玩的小游戏厅。纯前端渲染，房间与对局状态通过同源接口同步，手机、电脑都能进。

## 收录游戏

| 游戏 | 人数 | 说明 |
| --- | --- | --- |
| ⚫ 五子棋 | 2 人（多余进房自动变观战） | 轮流落子，先连成五子者胜 |
| 🐯 斗兽棋 | 2 人 | 象＞狮＞虎＞豹＞狼＞狗＞猫＞鼠，鼠能吃象；只有鼠能下水，狮虎可跳河吃子；攻入兽穴、吃光对方或困死对方即胜 |
| 🃏 欢乐扑克 | 2 - 6 人 | 创建时自定初始欢乐豆与大小注，支持加注、全押与多人边池结算 |

## 玩法

1. 打开页面，填一个昵称（写一次就记住）。
2. **创建房间**：选游戏、生成 4 位房间码。
3. 把房间码发给同学，对方在**加入房间**里输入即可同桌开局。

## 本地运行

需要 Node.js 18 及以上。

```bash
node server.js
# 打开 http://localhost:3000
```

也可用 `npm start`。端口通过环境变量 `PORT` 调整，默认 3000。

> `js/vendor/` 下是数据通道 SDK 的本地副本（一个压缩过的第三方库），未纳入版本库。`js/cloud.js` 会按 `SDK_URLS` 顺序依次尝试：本地副本 → unpkg → jsDelivr，本地缺失时自动走 CDN。

## 关于 server.js

`server.js` 做两件事：

1. 托管所有静态资源；
2. 把同源的 `/.ghproxy/*` 反向代理到云端数据服务。

之所以要代理，是因为云数据库按 `Origin` 做白名单校验，只认应用登记的域名。站点一旦跑在别的域名下（比如预览 / 沙箱域名），浏览器直连会直接 403。由服务端转发就不受浏览器同源策略限制，而页面本身仍然请求同源地址，不存在跨域。

转发时**只**挑选白名单请求头（`FORWARD_HEADERS`）送上去，其余一律丢弃——平台边缘会注入属于本应用会话的凭据，原样转发会让云端判定会话属于别的客户端而返回 401。

> 注：云端数据通道依赖宿主平台的托管环境（见 `server.js` 中的 `CLOUD_UPSTREAM`）。本仓库包含完整的前端与服务端代码，但直接克隆运行只能打开页面，联机功能需要接入自己的数据后端。

## 规则引擎

`jungle-engine.js` 与 `poker-engine.js` 是纯逻辑模块，不依赖 DOM，可以单独引入做单元测试或复用。
